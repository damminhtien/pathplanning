05 / HOW TO READ A MEASUREMENT

Don't stop at “how much faster?”

A useful benchmark says what was measured, on which task, against what checks, and what remains unknown.

01

Match the problem

Keep map type, motion rules, cost units, robot shape, and goal policy aligned.

02

Freeze the inputs

Record source, version, hashes, seed, and workload before planner runs.

03

Run a paired comparison

Keep start/goal pairs and protocol fixed; separate warmups, repeats, and run order.

04

Check independently

Validate endpoints, collisions, legal moves, and a separately reconstructed path cost.

05

Report what is missing

Show latency with solved coverage, quality, memory, timeouts, and unmeasured inputs.

Correctness

Is the route feasible? Does it reach the exact goal? Does independent cost reconstruction agree?

Time

Report medians and spread on matched workloads; separate setup cost when it matters.

Work

Expanded nodes, checked edges, and collision checks help explain how a runtime happened.

Memory

Separate peak memory from retained structures, query state, and result output.

Keep denominators visible. Success coverage counts eligible workloads selected before planner runs. Conditional latency on commonly solved cases belongs beside full-cohort coverage; repeat runs are not independent queries. Shortest-path evaluation contract
